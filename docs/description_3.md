 Отчет по 3 этапу - Web-интерфейс и обработка запросов

 1. Общая характеристика проекта

Проект представляет собой Spring Boot web-приложение для учебного центра. Система предназначена для ведения данных об обучающихся, преподавателях, компаниях, курсах, занятиях и расписании.

В приложении используются:

- Spring MVC для обработки HTTP-запросов;
- JSP для серверного рендеринга страниц;
- Hibernate / JPA для работы с данными;
- PostgreSQL в качестве СУБД;
- Gradle для сборки Java-кода и запуска тестов;
- Ant для подготовки базы данных, полной сборки, сборки WAR и развертывания;
- Selenium WebDriver + TestNG для системного тестирования web-интерфейса.

Приложение реализует интерфейс оператора/администратора учебного центра без разграничения ролей. Пользователь может просматривать справочники, создавать, редактировать и удалять сущности, записывать обучающихся на курсы, добавлять занятия и искать расписание.

 2. Структура итогового проекта

 2.1 Основной исходный код

`src/main/java/java_prac/`

- `JavaPracApplication.java` - точка входа в приложение и конфигурация основного сервлета для WAR-развертывания.

- `DaoConfig.java` - регистрация DAO-классов как Spring bean'ов.
- `WebMvcConfig.java` - web-конфигурация Spring MVC, настройка JSP view resolver и конвертера `String -> LocalDateTime`.
- `controller/`
- `HomeController.java` - главная страница.
- `CompanyController.java` - список, карточка, создание, редактирование и удаление компаний.
- `StudentController.java` - список, карточка, создание, редактирование и удаление обучающихся, запись обучающегося на курс.
- `TeacherController.java` - список, карточка, создание, редактирование и удаление преподавателей.
- `CourseController.java` - список, карточка, создание, редактирование и удаление курсов, добавление занятий курса.
- `ScheduleController.java` - форма поиска расписания и вывод результатов поиска.
- `service/`
- интерфейсы сервисов: `CompanyService`, `StudentService`, `TeacherService`, `CourseService`, `LessonService`, `ScheduleService`.
- `service/impl/`
- реализации бизнес-логики для компаний, обучающихся, преподавателей, курсов, занятий и расписания.
- `dao/`
- DAO-интерфейсы для доступа к данным.
- `dao/impl/`
- Hibernate-реализации DAO-классов.
- `model/`
- доменные сущности: `Company`, `Teacher`, `Student`, `Course`, `Lesson`, `CourseTeacher`, `StudentCourse`, `LessonStudent` и составные ключи связующих таблиц.
- `web/form/`
- form-классы для данных HTML-форм: `CompanyForm`, `StudentForm`, `TeacherForm`, `CourseForm`, `LessonForm`, `EnrollmentForm`, `ScheduleSearchForm`.
- `web/view/`
- view-модели для JSP-страниц: `CompanyDetailsView`, `StudentDetailsView`, `TeacherDetailsView`, `CourseDetailsView`, `ScheduleResultView`.
- `util/`
- `HibernateUtil.java` - инициализация `SessionFactory`.

 4. Конфигурация

 4.1 Конфигурация Spring

В проекте присутствует требуемая конфигурация Spring-приложения:

- `DaoConfig.java` регистрирует DAO-компоненты:
- `CompanyDao`;
- `StudentDao`;
- `TeacherDao`;
- `CourseDao`;
- `LessonDao`.
- `WebMvcConfig.java` настраивает:
- `InternalResourceViewResolver`;
- JSP prefix `/WEB-INF/jsp/`;
- JSP suffix `.jsp`;
- конвертацию строк из HTML-полей `datetime-local` в `LocalDateTime`.

4.2 Конфигурация основного сервлета / web-конфигурация

Приложение настроено как Spring Boot MVC-приложение с поддержкой JSP. Основная web-конфигурация задается в:

- `JavaPracApplication.java`;
- `application.properties`:
- `spring.mvc.view.prefix=/WEB-INF/jsp/`
- `spring.mvc.view.suffix=.jsp`
- `server.port=8080`

`JavaPracApplication.java` наследуется от `SpringBootServletInitializer`, что позволяет собирать приложение как WAR и разворачивать его во внешнем servlet container.

 5. Сценарии системного тестирования

Системные тесты реализованы с использованием Selenium WebDriver и TestNG. Они запускают Spring Boot web-приложение на случайном порту и проверяют работу через браузер Chrome в headless-режиме.

Тестовый класс:

`src/systemTest/java/java_prac/system/WebInterfaceSystemTest.java`

5.1 Проверяемые сценарии (`WebInterfaceSystemTest`)

1. Главная страница содержит ссылки на все основные разделы
 - открыть `/`;
 - проверить наличие разделов: обучающиеся, преподаватели, компании, курсы, расписание.

2. Компания может быть создана успешно
 - открыть `/companies/new`;
 - заполнить название и адрес;
 - отправить форму;
 - проверить открытие карточки созданной компании.

3. Создание компании без названия отклоняется
 - открыть форму добавления компании;
 - отправить пустую форму;
 - проверить сообщение валидации.

4. Создание компании с повторяющимся названием отклоняется
 - создать компанию;
 - повторно отправить форму с тем же названием;
 - проверить сообщение об ошибке сохранения.

5. Обучающийся может быть создан и записан на курс
 - создать нового обучающегося;
 - в карточке обучающегося выбрать доступный курс;
 - отправить форму записи;
 - проверить, что выбранный курс появился в списке курсов обучающегося.

6. Преподаватель может быть создан успешно
 - открыть `/teachers/new`;
 - заполнить ФИО;
 - выбрать компанию;
 - отправить форму;
 - проверить открытие карточки преподавателя.

7. Курс может быть создан успешно
 - открыть `/courses/new`;
 - заполнить название, описание, компанию, тип длительности и количество часов в день;
 - отправить форму;
 - проверить открытие карточки курса.

8. Создание курса с пустыми обязательными полями отклоняется
 - открыть форму добавления курса;
 - отправить пустую форму;
 - проверить сообщения валидации для названия, компании, типа длительности и часов в день.

9. Занятие может быть создано успешно
 - открыть `/courses/1/lessons/new`;
 - выбрать преподавателя;
 - указать корректное время начала и окончания;
 - отправить форму;
 - проверить, что занятие появилось в карточке курса.

10. Создание занятия с некорректным временем отклоняется
- открыть форму добавления занятия;
- указать окончание раньше начала;
- отправить форму;
- проверить сообщение об ошибке.

11. Поиск расписания обучающегося возвращает занятия
- открыть `/schedule`;
- выбрать поиск по обучающемуся;
- выбрать обучающегося;
- указать период;
- проверить страницу результата и найденные занятия.

12. Поиск расписания без выбора обучающегося отклоняется
- выбрать тип поиска по обучающемуся;
- не выбирать обучающегося;
- отправить форму;
- проверить сообщение об ошибке.

13. Поиск расписания без выбора преподавателя отклоняется
- выбрать тип поиска по преподавателю;
- не выбирать преподавателя;
- отправить форму;
- проверить сообщение об ошибке.

14. Поиск расписания с некорректным периодом отклоняется
- выбрать тип поиска;
- указать конец периода раньше начала;
- отправить форму;
- проверить сообщение об ошибке периода.

 6. Сборка, локальное развертывание и тестирование

6.1 Назначение `build.xml`

`build.xml` оркестрирует:

- подготовку базы данных;
- запуск DAO/unit-тестов;
- запуск Selenium-системных тестов;
- сборку WAR-архива;
- полную сборку проекта;
- копирование WAR-файла в каталог Tomcat для развертывания.

6.2 Основные Ant-target'ы

- `db-create` - выполнить `db/create.sql`;
- `db-init` - выполнить `db/init.sql`;
- `db-clean` - выполнить `db/cleanup.sql`;
- `db-reset` - очистка + создание + инициализация БД;
- `db-show` - показать количество записей в основных таблицах;
- `compile` - сборка основных классов через Gradle;
- `compile-tests` - сборка тестов;
- `test` - запуск DAO/unit-тестов;
- `system-test` - запуск Selenium-системных тестов;
- `war` - сборка WAR-архива приложения;
- `full-build` - полная сборка: `clean + test + bootWar`;
- `deploy` - копирование собранного WAR-файла в каталог `tomcat.webapps.dir`;
- `ci` - пересоздание БД и запуск тестов.

6.3 Инструкция по запуску приложения

 Предварительные условия

В системе должны быть установлены и доступны:

- Java 21;
- Gradle wrapper (`./gradlew`);
- Ant;
- PostgreSQL;
- клиентская утилита `psql`;
- Google Chrome или Chromium для Selenium-тестов.

Файл `build.properties` должен содержать корректные параметры подключения к БД:

- `db.host`;
- `db.port`;
- `db.name`;
- `db.user`;
- `db.password`.

 Подготовка базы данных

```bash
ant db-reset
```

 Запуск web-приложения

```bash
./gradlew bootRun
```

После запуска приложение доступно по адресу:

```text
http://localhost:8080/
```

Основные страницы для ручной проверки:

- `http://localhost:8080/companies`
- `http://localhost:8080/students`
- `http://localhost:8080/teachers`
- `http://localhost:8080/courses`
- `http://localhost:8080/schedule`

6.4 Полная сборка и развертывание

 Полная сборка

```bash
ant full-build
```

В рамках этой команды выполняется:

- очистка результатов предыдущей сборки;
- компиляция приложения;
- запуск DAO/unit-тестов;
- генерация JaCoCo-отчета;
- сборка WAR-архива.

Собранный WAR-файл находится в:

`build/libs/java-prac-0.0.1-SNAPSHOT.war`

 Развертывание во внешний Tomcat

В `build.properties` нужно указать каталог `webapps` установленного Tomcat:

```properties
tomcat.webapps.dir=/path/to/apache-tomcat/webapps
```

После этого выполнить:

```bash
ant deploy
```

 7. Итоговый результат

В результате выполнения этапа проект содержит:

- Spring MVC-контроллеры для всех основных разделов web-интерфейса;
- JSP-страницы для компаний, обучающихся, преподавателей, курсов, занятий и расписания;
